# 01: Session usage accounting as one module

**Status:** ready-for-agent

**Category:** bug

**Blocked by:** None (can start immediately)

**What to build:** Give job, dashboard, and report one importable Python module that reads Claude Code and Codex session directories and prices usage rows with the configured price table. A Codex session that changes models charges each increment at the rate of the model in use when those tokens accrued. Job and outside usage retain their respective rollups.

- [ ] Job sync records $3.00 and two model rows for a Codex fixture with one million input tokens at $1 per million followed by one million at $2 per million. The outside scan prices the same usage at $3.00 when the fixture has no job marker.
- [ ] Dashboard and report return the same outside-usage summary for the same session directories and price table. Factory sessions stay out of that summary.
- [ ] Direct tests import the module and turn temporary JSONL fixtures into usage rows. Changing the price table reprices cached usage without rereading transcripts.

A deeper Python module puts parsing and pricing in one implementation while letting job and outside adapters keep their existing attribution and rollups. That gives price changes locality and gives fixture tests leverage across all three consumers. The module's exact Python interface can be chosen during implementation.

## Agent Brief

**Category:** bug

**Summary:** Price session usage once through a shared Python module and fix Codex model attribution in job totals.

**Current behavior**

`cost_usd` and `codex_cost_usd` compute job costs. The dashboard repeats session parsing and price arithmetic for outside usage. `codex_cost_usd` applies the last model's rate to all cumulative usage. `scan_codex` assigns each positive token increment to the current model. Report gets outside usage by loading the dashboard executable.

**Desired behavior**

The shared module accepts explicit session directories and the price table and produces usage rows. Claude accounting uses message IDs and the existing fresh input, five-minute cache write, one-hour cache write, cache read, and output rates. Codex accounting uses cumulative counter growth and the active model. A repeated cumulative total contributes zero. A shorter copy of a resumed Codex session contributes no extra usage.

Job attribution uses the job brief and existing discovery scope. Job rows keep their role, agent, model, token, cost, and session-count fields. A session contributes once to each model's row for its role and agent. Outside usage excludes factory sessions and keeps its local-month and working-directory summaries, factory session count, and unpriced tokens by month and model. Job keeps its warning for unpriced models and charges zero for their tokens. Job accounting can price usage without a timestamp when attribution and token counts are available. Monthly outside totals use dated usage.

**Key interfaces**

- The session accounting module takes Claude project and Codex session directories plus `prices_usd_per_mtok`. Its rows carry the agent, model, token buckets, and attribution needed for job and outside rollups. Explicit inputs let tests use JSONL fixtures without touching the operator's session directories.
- `sync` consumes job usage and continues to populate `cost_by_agent`, `cost_breakdown`, and `cost_usd` with their existing schemas and rounding.
- `Outside.scan` and `scan_outside` produce the existing outside summary. Both consumers use a normal Python import. The outside cache keeps token counts so price-table changes can reuse cached scans.

**Acceptance criteria**

- [ ] A job-sync fixture switches from $1 to $2 per million after the first million input tokens and ends at two million. Sync records $3.00 for Codex and $3.00 for the job, with one session and one million tokens in each of two model rows. A repeated count and a shorter duplicate rollout leave the result at $3.00.
- [ ] A direct module test reads Claude JSONL with repeated message IDs and separately priced cache writes and reads, then verifies token counts and dollars. Tests cover an unpriced model, a malformed JSONL line, and a missing optional session directory.
- [ ] Dashboard and report agree on outside results for the same inputs. A fixture verifies Claude deduplication across transcripts, Codex model changes across local months, and factory-session exclusion. The accounting fixture imports the module directly.
- [ ] A repeat outside scan reuses unchanged transcripts. Previously cached usage still counts after its transcript is deleted, including when upgrading existing cache data. Updating the price table reprices those tokens.
- [ ] Existing single-model job costs, job row schemas and rounding, and outside summary fields satisfy the existing consumers.

**Out of scope**

- Subscription document ownership and unrelated subscription tests belong to ticket 06.
- Shared job summaries and JavaScript cost aggregation belong to tickets 05 and 07.
- Historical job backfills, price-table updates, and hub protocol changes.
