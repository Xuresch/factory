## Triage

**Verified:**

- Cost-by-role logic is spread across the five cited dashboard functions. `costTable` renders exact role, agent and model rows and sums their cost. `costsTables` uses `group` to total rows by role and model, with sliced roles labelled separately. `roleGroup` strips the slice suffix and folds unrecognised roles into Other. `bucketList` uses that mapping for chart shades, and `costsFor` uses it for per-role agent and model totals. These views need different levels of detail, even where their calculations overlap.
- The two bars duplicate agent selection and diverge in their text. Dashboard `splitBar` and `splitText` show amounts above $0.004. Hub `split` draws segments above $0.004, while its `splitText` and `legend` require at least $0.005. Running the functions in Node with a Claude-only $0.0045 split drew a segment on both pages. The dashboard labelled it “claude $0.00 (100%)” and the hub reported “no cost” with no legend entry. In the hub monthly API-equivalent bar, two $0.003 Claude source amounts produced a “claude $0.01” label and an empty bar.
- The input mismatch is real. For a $1 job without an agent split, dashboard `partsOf` returned $1 Claude and hub `byOf` returned $1 Other. `partsOf` also treats an empty split differently from a missing split, while `byOf` treats both as missing. Hub job projection has a separate residual rule for Other and discards residuals at or below $0.005.
- The dashboard's `group` and the hub's Rust job projection and overview rollups already cover parts of the calculation. None supplies a shared browser implementation of role aggregation and split visibility. `nav.js` shares navigation and live updates. The standalone dashboard loads independently of it. The repo has shell, Python and Rust tests, with no existing JavaScript test suite found.

**Recommendation:** ready-for-agent once 05 lands. The maintainer settled the visibility and attribution rules. One shared implementation gives the cost calculations locality and lets tests exercise the interface both pages use.

## Decisions

2026-11-20

- An agent is visible when its unrounded agent total is at least $0.005. The bar, accessible label, legend, and tooltip use that same selection.
- For a visible agent, draw every positive segment from factory jobs and outside usage, even if that segment alone is below $0.005.
- The JavaScript cost module reads each agent split only from ticket 05's job summary and applies no fallback. Ticket 05 owns attribution and assigns legacy total-only jobs to Claude.

## Agent Brief

**Category:** enhancement

**Summary:** Share dashboard role aggregation and agent split visibility in one JavaScript cost module.

**Current behavior:**

The dashboard calculates role totals separately for job detail, All tables, and Costs charts. Its ordinary bar and the hub's ordinary bar draw segments above $0.004, but the hub text and legend start at $0.005. The hub monthly API-equivalent bar also checks each source segment separately, so the label can name an agent that has no visible segment. The pre-05 dashboard and hub helpers apply different fallbacks when a job has no agent split.

**Desired behavior:**

The standalone dashboard, hub-served dashboard, and hub overview use one plain JavaScript cost module. Dashboard job detail retains exact role, agent, and model rows. All tables retains slice rollups, and Costs retains its role groups, role shades, and job, day, and week buckets. Both pages use the resolved agent split supplied by the job summary.

Use the unrounded agent total to select agents at or above $0.005. The bar, accessible label, legend, and tooltip agree on which agents are present. The hub monthly API-equivalent bar draws all positive factory and outside usage segments for each selected agent. The cutoff affects display only. Totals and the amounts used to calculate shares still include amounts below the cutoff.

**Key interfaces:**

- Ticket 05's job summary supplies the resolved agent split. The cost module consumes it directly, including explicit zeroes. Priced role, agent, and model rows supply role detail. Those rows are not a fallback for the agent split.
- The cost module supplies role and time-bucket aggregates and split display data. Both pages use the same selected agents and source segments to render their markup, including accessible text. Tests exercise the module through this interface without a DOM or server.

**Acceptance criteria:**

- [ ] In standalone factory-only mode, hub per-repo and all-repos dashboard modes, and the hub overview, the shared module loads and the relevant Costs views or agent split bars render. Standalone mode also works with the hub offline.
- [ ] A fixture with a sliced builder, a reviewer, and an unknown agent yields the original role, agent, and model detail rows, the expected slice rollups in All tables, and the existing role groups and shades in Costs. Job, day, and week bucket totals add up to the input amounts, empty day and week slots remain present, and toggling role shading preserves agent totals.
- [ ] A mixed split fixture with $0, $0.004, and $0.0045 amounts selects none of those agents. Each tested agent becomes visible at exactly $0.005. Check the bar, accessible label, legend, and tooltip against the same selection, and verify that amounts below the cutoff still contribute to the unrounded total.
- [ ] For the monthly API-equivalent bar, a $0.003 factory segment and a $0.003 outside usage segment for Claude both appear and share one Claude entry in the label, legend, and tooltip. A positive source segment also appears when the other source alone qualifies the agent. Zero source amounts and agents with combined totals below $0.005 have no segment.
- [ ] Run the same summaries through both job views and verify identical agent attribution for a legacy total-only job resolved as Claude by ticket 05 and for a supplied split containing explicit zeroes. A cost-module test verifies that a bare total supplies no synthetic agent split.
- [ ] Focused JavaScript tests cover the role aggregation, threshold, source segments, and summary consumption through the module interface without starting either server.

**Out of scope:**

- Usage accounting, outside usage attribution, Plan fee, and Monthly pace calculations.
- Navigation, chart layout, and visual redesign.
