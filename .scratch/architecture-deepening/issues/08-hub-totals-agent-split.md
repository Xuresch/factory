## Decisions

Made by the maintainer on 2026-11-20:

- The hub applies the Agent split rule at projection time and stores the result in the per-job agent columns; every aggregate only sums those columns.
- Existing rows are corrected by raising the projection version so the hub re-projects at startup; no SQL migration.
- The rule exists twice, in the Rust projection and in the browser job summary module (ticket 05), because the standalone dashboard is served statically. Both are tested against one shared fixture table. In hub mode the browser module takes the hub's projected split as given.
- The hub's subscription feed is not part of this ticket; ticket 06 switches it to the projected columns and is blocked by this ticket.

## Agent Brief

**Category:** bug
**Summary:** Make the hub's per-job agent columns follow the Agent split rule and re-project existing jobs, so every hub total agrees with the job card.

**Current behavior:**
The hub's job projection derives the per-job agent amounts from the stored split or the priced rows, puts any residue above $0.005 into other, and puts a job that has only a total into other. Repo, day, period and overview totals sum these columns, so a legacy total-only job is counted as other everywhere in the hub, while the dashboard counts it as claude.

**Desired behavior:**
The projection applies the Agent split rule: a stored non-empty split wins (explicit zeroes count) and a residue of at least $0.005 between that split and the total goes to other; otherwise the split comes from the priced rows with the same residue rule; a job with only a total is all claude. Residue under $0.005 is dropped. Raising the projection version makes the hub re-project all stored jobs at its next start. All aggregates keep summing the per-job columns and need no change of their own.

**Key interfaces:**
- The job projection's per-job agent amounts (claude, codex, other): computed by the rule above.
- The projection version: raised, so `Hub::reproject` corrects stored rows.
- A shared fixture table (jobs in, expected split out) in a language-neutral format (JSON), read by the Rust tests and by the node tests of ticket 05's job summary module.

**Acceptance criteria:**
- [x] Rust tests over the shared fixture table pass for: stored split, stored split with explicit zeroes, stored split with residue above and below $0.005, priced rows only, total only, zero-cost job.
- [x] The same fixture table passes against ticket 05's browser job summary module under node.
- [x] A hub started on a database projected by the previous version re-projects the jobs, and the legacy total-only job then appears as claude on its card, in its repo total, in its day/period total and in the overview.
- [x] The existing hub tests still pass.

**Out of scope:**
- The subscription feed and the monthly comparison (ticket 06).
- Chart drawing and the visibility threshold for splits (ticket 07).
- Any change to how the factory writes the split into job.json.
