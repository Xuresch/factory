# 05: One job summary for local and hub

**Status:** ready-for-agent

**Category:** bug

**Blocked by:** None (can start immediately)

**What to build:** Route local and hub jobs through one browser-side job summary module. The module resolves the Agent split once, so the header, tables, charts, drawer summary, and overview job cards agree on what each agent cost. Both adapters supply the same summary fields and offer the same drawer detail operation.

- [ ] Run the same fixtures through both adapters. A non-empty stored split wins over conflicting priced rows, including explicit zeroes. Missing and empty splits use priced rows. A $12 total-only job reports $12 Claude and $0 Codex and Other. Unknown agent amounts go to Other, and a $0.004 residue is dropped without changing the recorded total.
- [ ] With the same set of jobs, the header, board, drawer summary, Costs table values and sort order, agent charts, and hub overview job cards use the same Agent split. Switching chart shading preserves agent totals. Any Subscription display for an individual job uses the same Agent split.
- [ ] Exercise static local serving, a single hub repo, and all hub repos. Shared renderers use summary fields for identity, repo labels, round Verdicts, timing, and costs without checking the hub flag. Duplicate job keys from different machines remain distinct, and job hash links open the intended drawer.
- [ ] Open a drawer and list and read its documents through the same detail operation in both modes. A missing document retains the existing unavailable state, and a late detail response cannot replace the drawer for a different job.
- [ ] Hub repo and period totals produce the same values for the same stored records before and after this change.

## Triage

**Verified:**

- Cost attribution is duplicated. `render` and the `costsTables` totals and job columns read missing agent amounts as zero. `partsOf` attributes a missing split to Claude and folds unfamiliar agent keys into Other. `agentCost` also defaults missing splits to Claude for the Subscription comparison. `byOf` in the hub overview defaults absent or empty splits to Other. The Rust `project` implementation prefers a supplied split over priced rows for Claude and Codex and derives Other from the positive remainder above half a cent. These are the six cited places. The count is a lower bound because `costTable` and `bucketList` also sum priced rows first for the drawer and charts.
- Reproduced a visible mismatch in a temporary directory by running the current `render`, `bucketList`, `agentCost`, and `byOf` against a $12 legacy job with no split or priced rows. The local header showed $12 total with $0 for Claude and $0 for Codex. The agent chart and Subscription lookup assigned $12 to Claude. The isolated overview fallback assigned $12 to Other. That last result exercises the helper directly. Normal hub overview jobs already arrive with a projected split.
- `loadJobs` returns raw job JSON locally and projected summaries on the hub. `roundVerdicts` reads local verdict files or hub round fields, `times` computes local durations from history or reads hub durations, and `refreshDrawer` uses the local file listing or fetches hub job detail. Fourteen dashboard lines between `roundVerdicts` and the completed-job row reference `hub` when polling status is excluded. They include transport and repo label selection, so fourteen renderer branches to delete is an overcount. `render` itself has no hub conditional.
- Checked existing job producers, the dashboard readers, and hub projections for a shared implementation. `sync` writes the current split and priced rows. The hub's `summaries` already backs job lists, detail, and overview jobs, but local mode bypasses it. Local `subscriptions` forwards a reduced job document, while hub `subscriptions` builds a Claude/Codex map from stored columns and omits zero entries. The hub overview also sums those stored cost columns for repo totals. No existing module owns attribution and the summary interface across both sources. No prior rejection was found in the checkout.

**Recommendation:** ready-for-agent. The reproduced discrepancy establishes the bug. The maintainer settled the fallback order, the module that owns it, and the drawer detail seam.

## Decisions

- **2026-11-20.** A non-empty stored Agent split wins, including explicit zeroes. Otherwise use the priced rows. A total-only job is entirely Claude because the factory counted only Claude transcripts before 2026-11-12, when commit `de2e902` introduced stored splits and Codex counting. Drop residue below $0.005. This supersedes the earlier recommendation to assign a total-only job to Other.
- **2026-11-20.** One shared browser-side job summary module applies this rule in local and hub job views. Ticket 08 covers hub repo and period totals.
- **2026-11-20.** The summary carries identity, display fields, Verdicts, timing, and costs. Both adapters expose a separate detail operation for drawer file listings and document reads.

## Agent Brief

**Category:** bug

**Summary:** Give local and hub job views one job summary and one Agent split rule.

**Current behavior:**

A $12 legacy job without a stored split or priced rows shows $0 for Claude in the local header and $12 for Claude in the agent chart. The drawer and chart also re-sum priced rows even when a stored split exists. Local jobs arrive as raw job records, while hub jobs arrive with projected timing, Verdicts, and costs. The hub projection can hide whether zeroes came from the source record or were filled in later.

**Desired behavior:**

The local and hub adapters return the same job summary interface. One shared browser-side module resolves the Agent split from the original cost evidence. It uses a non-empty stored split first, including explicit zeroes, then priced rows if the split is missing or empty, then assigns a total-only legacy job entirely to Claude. It groups unfamiliar agents under Other and drops residue under $0.005 while retaining the recorded job total. Every per-job display uses those resolved amounts, including when priced rows are present and chart shading changes. Hub repo and period totals stay as they are for ticket 08.

The summary supplies identity, display fields, round Verdicts, timing, and costs in both modes. Missing Verdict artifacts remain pending, and an unreadable first line remains invalid. The shared renderers use summary fields and the adapter detail operation. File listings and document reads remain available on demand, including under static local serving, and the drawer keeps its current behavior for missing documents or late responses.

**Key interfaces:**

- Job summary. Carries identity that is unique in the active view, display fields such as title, repo, and job stage, round Verdicts, timing, the recorded cost total, and the resolved Agent split.
- Local and hub adapters. Provide the shared module with the original attribution evidence it needs, including whether a non-empty split was recorded and the priced rows for fallback. Derived zeroes must preserve the ability to distinguish an explicit stored zero from a missing split.
- Drawer detail operation. Takes the same job identity in either mode and provides its file listing and requested document on demand.
